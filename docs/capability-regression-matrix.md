# Capabilities 固定回归矩阵

权限判断以服务端返回的 `users.capabilities` 为最终依据。前端隐藏入口只属于体验层，不能替代 API 鉴权；每次修改认证、角色、权限或治理路由时，都必须执行 `go test ./...` 并检查这张矩阵。

| 身份 | 发帖 | 评论 | 点赞 | 收藏 | 投票 | 举报 | 审核 | 管理员管理 | IP 封禁 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `anonymous` | 否 | 否 | 否 | 否 | 否 | 否 | 否 | 否 | 否 |
| `guest_user` | 否 | 是 | 是 | 否 | 否 | 是 | 否 | 否 | 否 |
| `normal_user` | 是 | 是 | 是 | 是 | 是 | 是 | 否 | 否 | 否 |
| `admin` | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 否 | 是 |
| `super_admin` | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 是 | 是 |

## 回归要求

- 游客后端身份仍然是 `users.account_type=guest`，允许可追踪的评论、点赞、举报，但不能发帖、创建投票或管理收藏夹。
- `admin` 的审核、审计读取和全局 IP 封禁能力来自角色权限；管理员管理只对 `super_admin` 开放。
- 新动作必须先补充服务端 capabilities 映射和本表，再补前端入口；禁止出现“前端隐藏但 API 可调用”或“API 拒绝但前端误显示”的分叉。
- `anonymous` 表示未建立认证用户上下文，不是一个可写入业务数据的 guest session。
